# 진단 및 정리 동작의 한계

## 이번 수정

- 프로세스 수집은 15초 간격으로 작업 스레드에서 실행합니다. 중복 검사는 실행하지 않습니다.
- 로컬 포트 검사는 작업 스레드에서 실행합니다. 실패 시 안전하다고 표시하지 않습니다.
- 페이지 파일은 EnumPageFilesW의 TotalInUse/TotalSize로 측정합니다. 이전 버전은 커밋 관련 값을 페이지 파일로 표시했습니다. 과거 기록은 수정하지 않으며 새 측정과 직접 비교하지 마세요.
- Windows 측정 실패는 0으로 학습하거나 자동 처리하지 않습니다.
- RAM이 기준을 연속 3회 초과할 때만 자동 처리합니다. 낮은 참고 점수만으로 정리하지 않습니다.
- 정리는 Memory Guardian 자체 작업 집합만 축소합니다. 다른 프로그램 종료, 전체 작업 집합 축소, 대기 캐시 강제 비우기는 하지 않습니다.
- 알림 전용 모드는 정리 횟수에 포함하지 않고 10분간 반복 알림을 억제합니다.
- 정리 후 감소량은 관측 결과이며 인과관계나 회수 효과를 증명하지 않습니다.

## 해석 주의

점수는 규칙 기반 참고 값이며 AI 진단, 누수 확률 또는 성능 향상 보장이 아닙니다.
프로세스 RAM은 작업 집합입니다. 공유 페이지가 중복 집계될 수 있으며 증가 원인 비중이 시스템 전체 증가 비중을 의미하지 않습니다.
누수 판정은 작업 집합이 아니라 Private Bytes(전용 커밋)를 사용합니다. 최근 1시간에서 최소 30분 연속 기록, 5분 구간 중 75% 이상 증가, 합계 384 MB 이상 증가(개발자 모드 768 MB), 시간당 128 MB 이상 증가, 큰 회수 미관측 조건을 함께 요구합니다. 이는 검증된 확률 모델이 아니라 보수적인 관찰 규칙이며 정상 작업도 조건에 해당할 수 있습니다. 확정 진단에는 해당 프로그램의 할당 추적이 필요합니다.

시작 시각이 다른 동일 PID는 기록을 초기화합니다. 시작 시각을 읽지 못한 프로세스는 누수 판정을 보류합니다. 2분 초과 측정 공백은 연속 분석을 다시 시작합니다. 이력은 30초 간격으로 최대 24시간 보관합니다. 날짜가 바뀌어도 연속 관측을 유지하지만 앱 재시작 후에는 다시 관측합니다.

새 설치의 정리 방식은 알림 전용이며 기존 사용자 선택은 유지합니다. 자체 정리를 선택하면 32 MB 미만의 작업 집합은 건너뜁니다. API 성공 여부와 Windows 오류 코드, 자체 작업 집합 전후 값을 기록합니다. 8 MB 이상 감소가 관측되면 최소 10분, 그 외에는 20/40/60분으로 재시도 간격을 늘립니다. 이 감소량은 영구 회수량이 아닙니다. 의심 프로세스는 자동 종료하거나 재시작하지 않습니다.

10분 간격 프로세스 CSV는 새 `-processes-v2.csv` 파일에 전용 커밋, 시작 식별자, 판정 근거를 함께 기록합니다. 과거 파일은 변경하지 않습니다. 누수 의심 시작/해제는 활동 로그에 기록합니다.
프로세스 존재만으로 서비스 연결 상태를 판정할 수 없습니다. 로컬 수신 포트만으로 인터넷 노출 여부를 판정할 수 없습니다.

## 남은 검증 과제

장기 학습 신뢰도, 커널 증가 해석, 실제 PC에서의 장시간 UI 응답성은 추가 검증이 필요합니다. 드라이버 누수 확정과 다른 프로세스의 할당 해제는 지원하지 않습니다.
